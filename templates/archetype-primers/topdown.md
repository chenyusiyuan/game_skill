# Topdown 品类 Primer

> 适用于“俯视角冒险”“地牢房间战斗”“俯视角探索”“Zelda-like”“俯视角收集”的 query。
> topdown 是视角和交互结构，不等于某一个固定题材。

## 别名

- 中文：俯视角 / 上帝视角 / 顶视角 / 地牢探索 / 房间战斗 / 迷宫冒险。
- 英文：topdown / top-down adventure / Zelda-like / dungeon crawler / arena room.
- 代表作：早期 Zelda / Binding of Isaac / Enter the Gungeon / Hyper Light Drifter。
- 关键识别词：四向移动、房间、钥匙、门、敌人、宝箱、机关、探索。
- 近邻但不同：shooter 重火力弹幕；survivors 重怪潮升级；grid puzzle 重离散格逻辑。

## 品类公约

- 玩家可在二维平面自由移动，碰撞边界要清楚。
- 地图由房间、区域或小场景组成，目标通常是钥匙、出口、宝箱或敌人清场。
- 交互物需要明确可达性：门、开关、障碍、拾取物都要有视觉差异。
- 战斗若存在，敌人要有接近、巡逻、冲刺或远程至少一种行为。
- 摄像机可以固定或轻微跟随，但不要让 HUD 随地图飘走。
- 玩家攻击或互动必须有朝向、范围或提示。
- 受伤反馈要包含短无敌和击退，避免连续碰撞扣血。
- 目标路径要短而确定，first-cut 不适合做大迷宫。
- 颜色编码很重要：钥匙、门、危险、奖励不能混色。
- 完成条件应能被玩家看见，如门打开、宝箱发光、出口亮起。

## 经典反馈瞬间

| 瞬间 | 可执行反馈 |
|---|---|
| 拾取钥匙 | 钥匙跳向 HUD，门锁图标亮起，短音上扬 |
| 打开门 | 锁裂开，门板向两侧滑动，出口光晕增强 |
| 击中敌人 | 敌人白闪 80ms，后退 12-24 px，伤害数字弹出 |
| 玩家受伤 | 红闪，短无敌闪烁，向伤害来源反方向击退 |
| 触发开关 | 开关压下，连线或地砖逐段亮起 |
| 宝箱开启 | 盖子弹开，奖励上跳，周围闪星 |
| 房间清场 | 门解除封锁，房间边框由红转绿 |
| 出口可用 | 出口地砖脉冲，箭头或光束提示方向 |

## 常见 mistake

1. 地图太大，smoke 和玩家都找不到目标。
2. 墙体、门、地面颜色接近，碰撞边界不清楚。
3. 敌人只贴脸追，玩家没有战术空间。
4. 攻击没有范围提示，玩家不知道打没打中。
5. 钥匙和门没有对应关系，目标链断裂。
6. 受伤没有无敌窗口，碰撞一次掉多格血。
7. HUD 放在游戏世界里，移动时看不见。
8. 摄像机跟随太硬，输入时画面晃动影响判断。
9. 互动键太多，first-cut 变复杂。
10. 结算只改状态，不给出口、光效或文字反馈。

## 数值起点

- 玩家速度：140-220 px/s；冲刺可 300 px/s 但有冷却。
- 玩家尺寸：24-36 px；碰撞体可比显示小 10-20%。
- 房间尺寸：640x480 内一屏可完成；走廊宽度 64-96 px。
- 近战范围：36-56 px；冷却 0.35-0.65 秒。
- 敌人速度：60-130 px/s；冲刺敌 180 px/s 但预警 0.4 秒。
- 玩家生命：3-5；受伤无敌 0.8-1.2 秒。
- 击退：玩家 20-40 px；敌人 12-28 px。
- 钥匙数量：first-cut 1-3 把；门锁数量和钥匙一一对应。
- 机关延迟：开关到门反馈 0.2-0.6 秒，太长会误解。
- 拾取半径：20-36 px；重要道具可用 48 px。
- 房间目标：30-90 秒完成一个小闭环。
- first-cut 目标：一个房间、一个门链、1-2 种敌人、一个胜利出口。

## 不要照搬

- 不要照搬 Zelda、Isaac 等作品的角色、道具名、房间图案。
- 如果 query 只要探索，不必塞进战斗；可以用钥匙门和机关做闭环。
- 如果 query 强调战斗，房间布局要给躲避空间，而不是空白矩形。
- 如果 query 是解谜向，敌人可以取消，保留明确目标链。
- 如果 query 是恐怖向，画面可暗，但可交互物必须高对比。
- 如果首交付时间紧，优先做移动、碰撞、目标物、门或出口反馈。
- 任何偏离品类公约的选择，都要在 decisions 里说明理由。
